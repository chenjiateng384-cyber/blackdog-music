## 1. 到底是什么项目

对外一句话：

> 黑狗音乐是一款面向私人收藏的 Android 本地音乐播放器，保留真实音乐目录，支持本地封面、LRC、歌单和数据备份，并附带可选的电脑音乐整理与歌词工具。

项目由两部分组成：

- **手机播放器**：Flutter 页面、Android 原生文件访问与媒体能力、SQLite 本地数据；用户自己提供音乐。
- **电脑后勤**：入库检查、AI 协作规则、目录与标签建议、歌词对齐及验收说明；不是手机内置下载器。

它不是在线曲库服务、音乐下载站、Apple Music / QQ 音乐客户端，也不是已经完成的多端云音乐平台。不随 App 附送私人音乐、完整商业歌词、账号或模型。

“Harmony”可保留为内部历史名称，但对外标题统一“黑狗音乐”，减少用户以为两个项目的混淆；本轮不批量改包名、数据库名和业务标识。

## 2. 适合谁，不适合谁

| 人群 | 是否合适 | 原因 |
| --- | --- | --- |
| 已有 FLAC / MP3 / WAV 等本地收藏的 Android 用户 | 核心人群 | 愿意自己管理目录、标签、封面与歌词 |
| 不想要广告、社区和在线推荐流的收藏者 | 合适 | 产品围绕个人音乐，不围绕平台内容 |
| 想学习本地播放器、扫描、备份和歌词处理的开发者 | 合适 | 提供源码、合成测试与操作边界，仍有维护和跨设备验收工作 |
| 第一次使用本地播放器的普通用户 | 发布包与新手说明齐备后可尝试 | 无须编译，但需要自行准备音乐并授予目录权限 |
| 想打开就在线搜歌、免费下载所有音乐的人 | 不合适 | 不提供在线版权曲库和下载服务 |
| iPhone 用户 | 当前不合适 | 没有 iOS 版本 |
| 希望已有成熟商业软件同等级全机型保证的人 | 暂不合适 | 目前是一加13为主的测试候选项目，不能承诺没有 Bug |

## 3. 推荐叫什么、在哪里发布

建议：

- 产品中文名：**黑狗音乐**。
- 英文展示名：**Black Dog Music**。
- GitHub 仓库名：**`blackdog-music`**。
- 仓库简介：`Android 本地音乐播放器，面向私人收藏，支持真实目录、封面、LRC、歌单与数据备份。附电脑端音乐后勤工具。`
- 自有代码：沿用已经选定的 MIT；第三方内容单独遵循原许可。

这是命名建议，不是已经注册的商标、占用检查结果或已创建仓库；在用户账号下创建前再核对名称。

推荐**一个源码仓库 + Android 预发布安装包**。电脑工具先放同一个仓库，不拆成多个缺维护人手的项目。不在这一轮同时上 Google Play、国内商店和 App Store。

先建私有仓库验证，再由所有者确认公开。GitHub Releases 用来放安装附件和版本说明；它基于 Git Tag，并自动提供对应源码归档。[GitHub Releases 官方说明](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases)

首次公众测试应标为 **Pre-release（预发布）**，不称 1.0 正式稳定版。Tag 示例 `v0.4.7-beta.1` 只是下一版命名建议，须在最终版本与提交确定后再创建；本轮没有改版本或打 Tag。[官方发布操作](https://docs.github.com/en/repositories/releasing-projects-on-github/managing-releases-in-a-repository)

## 4. Android 与苹果必须分开说明

| 平台 / 文件 | 当前实际状态 | 应怎样写下载区 |
| --- | --- | --- |
| Android ARM64 `.apk` | 已有 0.4.6 本地测试包；包内最低 API 24、target 36 | “Android 测试版”；正式公众包待专属签名与验收 |
| Android 32 位 / x86 | 当前交付包没有对应 ABI | “本次未提供”，不写通用全机型 |
| iPhone / iPad | 没有 `ios/` 工程、IPA、TestFlight 或 App Store 链接 | “暂不支持 iOS”，不放假按钮或承诺日期 |
| Windows / macOS / Linux 手机同款播放器 | 没有对应工程和桌面安装包 | “未提供桌面版” |
| 电脑 Python 工具 | 源码中可选使用，已在本机测试 | 单独标“电脑工具”，不是 `.exe` 播放器或苹果安装包 |
| GitHub `Source code.zip` / `.tar.gz` | 对应提交的源码归档 | “开发者源码”，不能当手机安装文件 |

Android 当前实际支持范围应写“Android 7.0+、64位 ARM、主要验收一加13”，并说明不能保证所有编码变体和厂商后台策略。设计图里使用某种手机外框不代表已支持那个平台。

### 为什么不能顺手给一个苹果包

项目中的扫描、目录授权、备份文件选择等通过 Android 原生接口实现，不能仅凭 Flutter 就自动得到可用 iOS 版。将来要做苹果，需要单独的 iOS 工程、文件访问与后台音频适配、签名和 iPhone 验收。

Flutter 官方要求用 macOS 与 Xcode 构建和发布 iOS；公开 App Store 还涉及 Apple Developer Program。推荐未来先走 TestFlight 测试，而不是把 IPA 当 Android APK 一样发给所有人安装。[Flutter 官方指南](https://docs.flutter.dev/deployment/ios)、[Apple TestFlight](https://developer.apple.com/testflight/)

现在不用为尚未立项的苹果版购买账号、Mac 或承诺交付日期。

## 5. 具体发什么、不发什么

### 源码仓库

保留经审阅的：

- `lib/`、`android/`、`shaders/`：App 实现。
- `test/`、原生测试、`.github/`：回归和自动检查配置。
- `pubspec.yaml`、`pubspec.lock`、必要构建配置与脚本：复现环境。
- README、MIT、第三方声明、隐私、安全、贡献与使用文档。
- `tools/harmony-music-intake/` 与已有歌词工具：通用电脑后勤能力；第三方源码和模型本体不打包。
- 经核对授权、脱敏且明确版本的少量演示图。

不提交：音乐、个人 LRC、真实数据库、备份、私钥、密码、浏览器状态、私人 WorkBuddy 完整目录、`.local-review/`、`.tooling/`、`.dart_tool/`、`build/`、`dist/` 与调试截图。

历史源码本身仍可能包含旧路径、旧素材和过时报告；忽略规则不清除已入 Git 的内容。发布前审当前候选与历史，不为图省事删掉用户本地原件或直接改写原历史。

### GitHub Release 的用户附件

正式准备好后，建议只放这些：

| 附件 | 用途 |
| --- | --- |
| `blackdog-music-v版本号-android-arm64.apk` | 经专属签名、验证的 Android 安装包；当前尚未生成这份公众包 |
| `SHA256SUMS.txt` | 让下载者核对文件是否与发布物一致，不等于来源认证或无漏洞保证 |
| 版本说明 | 新增/修复、测试设备、已知问题、备份与升级注意事项 |
| `LICENSE` 与第三方声明 | 说明所分发内容的许可；APK 相关声明必须能随发布物找到 |

源码直接使用 GitHub 自动生成的归档，不额外上传整个电脑文件夹。旧测试 APK、本机私钥和真实歌曲不附在 Release 中。

### 展示材料

准备首页、音乐库、播放页各一张**当前版本**截图，以及一个目录选取到播放的小演示。只用自己创作或许可明确的内容，检查通知栏和路径。已有 `docs/ui-mockups/` 是历史资料，不能直接作为“当前版本截图”误导新用户。

## 6. 新手将来怎样下载与使用

以下是正式链接存在后的流程，不代表今天已经公开：

1. 打开项目 GitHub 页面，先看“平台与下载”。
2. 进入 Releases，选择明确标为 Android 的预发布版本。
3. 在 Assets 中下载 `.apk`，不要选“Source code.zip”；当前只提供 ARM64 时按说明核对设备。
4. 阅读已知问题和升级说明。首次安装按 Android 提示为实际下载来源授予安装权限，不关闭系统安全防护；遇到不符的安全提示先停止核实。
5. 已有安装时先导出外部备份。签名不一致或版本过低就停下，不用卸载或清数据强行安装。
6. 准备自己有权使用的音乐，复制到手机固定目录，在 App“我的”选择音乐根目录并扫描。
7. 先检查几首中文、英文、WAV、合作曲与 Live，再建立喜欢和歌单。
8. 导出 `.harmonybackup` 到 App 外部并另存一份；音乐原件另备份，二者不能互相替代。

详细收歌和入库见[收藏指南](LOCAL_MUSIC_COLLECTION_GUIDE.md)，AI 配合见[音乐后勤](MUSIC_OPERATIONS.md)。Android 与苹果的下载入口保持独立：苹果在没有版本时写“暂未提供”，而不是让用户尝试安卓包。
