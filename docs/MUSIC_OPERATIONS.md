# 黑狗音乐后勤：架构、缺口与 AI 协作

更新：2026-11-04。定位：让“找到想收藏的音乐”稳定走到“手机上每天能听”，作为私人音乐库项目的电脑与 AI 协作部分。

第一次做，先读[从零打造私人音乐库](LOCAL_MUSIC_COLLECTION_GUIDE.md)。本文用于把具体工作交给 WorkBuddy、豆包或其他具备对应工具能力的 Agent（任务型 AI 助手）；不是要求安装所有 AI 工具，也没有把这些任务变成 App 内置功能。

工具与阶段检查的基线来自 2026-11-03；2026-11-04 补充网站入口、用户完整路线与 H/I/J 三组提示词，没有因此重新下载音乐、运行对齐模型或宣称历史检查是本次新验收。

## 1. 现在需要补的不是另一个播放器

项目分为两个相互配合、但不应混在一起的部分：

| 部分 | 负责什么 | 当前边界 |
| --- | --- | --- |
| 手机 App | 扫描、浏览、播放、喜欢、歌单、历史、App 数据备份 | 保持本地、只读原音乐；不把下载站账号和电脑自动化塞进 APK |
| 音乐后勤 | 获取、版本确认、目录标签、封面歌词、查重、同步与收藏备份 | 在电脑和用户控制的目录运行；有些任务需联网，有些需试听 |

WorkBuddy 已积累后一部分的大量经验，但技能、脚本、历史清单散落，缺少统一的输入、验收和交接。历史记录只能证明当时的操作，不能代表文件现在完整、来源仍可用，或模型对齐已经听感正确。

当前最合适的是接好流程，而不是开发新的服务器、下载平台、推荐模型或曲库数据库。

## 2. 目标链路与每一步的完成证据

```text
想收的歌 → 核对录音版本与来源 → 下载到暂存副本 → 只读检查
                                             ↓
独立备份 ← 手机验收 ← 增量复制与扫描 ← 标签/封面/歌词小批修正与试听
```

| 环节 | 输入与产物 | 由谁判断完成 |
| --- | --- | --- |
| 想收什么 | 歌名、歌手、版本、优先级；信息不够不猜 | 用户选择，AI 协助定位 |
| 从哪里取得 | 来源页面、核对日期、获取方式、用途说明 | AI 查询；涉及账号、费用或授权不明确时由用户决定 |
| 下载到哪里 | 用户指定暂存目录、实际下载清单、失败清单 | 下载成功后仍需核对版本；不能以页面成功代替音频检查 |
| 检查是否已有 | 当前文件清单、同名候选、精确重复候选 | 工具提供证据，AI 解释，删除另行确认 |
| 整理什么 | 原值与建议值、源/目标路径、需保留资源、回退方式 | 用户确认改写范围；先处理副本 |
| 补什么附件 | 图片来源与匹配、歌词版本、格式与试听结果 | AI 辅助，人检查疑点；无歌词需求也可以标“不适用” |
| 是否同步成功 | 目标相对路径、复制结果、手机重扫和抽样播放 | 电脑与手机分别验证，不互相代替 |
| 能否长期保存 | 音乐副本与 App 外部备份，恢复演练记录 | 两种备份都具备；不拿唯一数据做卸载实验 |

每批记录放在本地，不需要为此新增 SQLite 表或线上服务。

## 3. 缺口与本轮补齐程度

| 优先级 | 现有缺口 | 本轮处理 | 尚未完成的边界 |
| --- | --- | --- | --- |
| P0 | 旧标签脚本可能丢内嵌资源，旧清理脚本可能直接删文件 | 明确停用为默认执行工具；技能要求预演、备份与副本 | 没有改写 WorkBuddy 原脚本，也没有运行它们 |
| P1 | 旧 inventory 和补全报告易被当成当前事实 | 新增只读附件清单与可选精确查重；实际报告只留本地 | 不是完整音频解码、内嵌 Metadata 或母带鉴定器 |
| P1 | 下载来源、录音版本和公开许可混为一谈 | 来源登记与逐项决策流程；保留旧私有入口的位置 | 不保证任一第三方站仍可用，不假称所有歌曲都有可下载音源 |
| P1 | AI 各做一段，没有统一交付标准 | 本文提示词、批次模板、项目技能 | 不自动接管用户账号，不替用户确认含糊的歌曲版本 |
| P1 | 歌词对齐成功被当成咬字准确 | 接回现有对齐工具，保留小批试听与低置信度报告 | 没有重新处理整库歌词，普通 LRC 仍不含逐字事实 |
| P2 | 手机复制后没有闭环 | 同步前清单、复制后核验和 App 验收步骤 | 未新增自动同步器，未经授权不移动手机音乐 |
| P2 | 私人音乐后勤与公开源码边界模糊 | 通用指南和技能可供审阅；个人报告与入口表独立保管 | 正式发布仍受既有许可、签名和远端验收条件约束 |

## 4. 来源与工具怎样选

### 音乐文件

优先艺术家 / 唱片公司明确提供的文件，或支持普通音频下载的正规商店。例如 Bandcamp 官方提供购买后的格式选择；从官方下载页取得文件，不需要在 App 内接入下载站。[官方说明](https://get.bandcamp.help/en/articles/15263234-in-which-formats-can-i-download-my-purchases)

这不保证能找到用户指定的所有中文歌曲。中文平台的发行页可帮助确认作品，但能搜索、能离线听，不等于能授权导出普通文件。查不到合适音源时记录缺口，不用不明来源填满。

WorkBuddy 的两个常用入口已按所有者要求整理在[音乐获取指南](LOCAL_MUSIC_COLLECTION_GUIDE.md#2-从哪里获取音乐)：`flac.music.hi.cn` 与 `www.xmwsyy.com`。来源技能和私人路径仍保存在本机，原件未删除；网页当前状态、附件与授权逐项核对，不能因过去成功过就默认可批量获取或再分发。

### 标签与发行信息

[MusicBrainz Picard](https://picard.musicbrainz.org/quick-start/) 可辅助比对录音和发行；保存前核对原值与新值。它不是保证中文曲库完整、也不是零散单曲一键全修的工具。没有可靠结果时保留原值。

已有 Android 标签解析测试用于验证 App 能否读取，不是电脑端批量写标签工具，不能直接拿来重写原音乐。

### 封面

先看购买附件、官方资料和自己选择的图片。发行信息明确时，可参考 [Cover Art Archive 的发行封面入口](https://musicbrainz.org/doc/Cover_Art_Archive/API)；API 提供图片不等于授予再分发权。歌手照片和专辑图分别核对，不能互相替代。

### 歌词与 AI

优先匹配当前音频的授权文本 / LRC。已有[歌词对齐工具](../tools/lyrics_alignment/README.md)处理“可信文本 + 准确音频 → 时间轴草稿”，不负责寻找授权音源，也不保证所有停顿和快唱一次对齐。模型下载、耗时和试听工作不能省略。

本轮新工具只盘点外置附件和时间标签类型，不从音频自动识别歌词、不下载模型、不上传音频。

## 5. 已有技能保留什么

| WorkBuddy 资源 | 值得保留的经验 | 默认执行方式 |
| --- | --- | --- |
| `flac-music-download` | 曾用来源、版本识别、下载后核验的线索 | 网站入口与通用流程已整理，原技能作为本机资料；不复制或执行会话接管与绕验证命令 |
| `music-collection-guard` | 同名不同录音、合作和版本识别 | 当前目录优先，旧 inventory 辅助；不把翻唱等同未授权 |
| `music-library-organizer` | 整理预演、真实目录、标签字段与备份 | 通用经验保留；旧写入脚本不直接用于原件 |
| `music-phone-sync` | 增量复制、附件、Unicode 路径和传输验收 | 先小批验证；不默认镜像删除或批量改名 |
| `qqmusic` 市场技能 | 作品与发行信息的辅助检索线索 | 需要当前授权与服务能力；不把接口凭据复制进公开仓库 |
| 本项目歌词工具 | 格式转换、对齐及验证流程 | 复用现有实现和许可证，先小样本，不另造一套 |

新增的[音乐后勤技能](../tools/harmony-music-intake/SKILL.md)负责统一路由与交接，不替代所有专业工具。它是可随项目审阅的文件，未修改 Codex 或 WorkBuddy 的全局配置；其他 AI 环境可手动读取，不声称所有环境自动识别。

## 6. 只读工具怎么用

需要电脑已有 Python 3.10 或以上，无额外 Python / Flutter 依赖。在项目根目录运行，把示例目录替换为实际音乐目录，批次号每次换新：

```powershell
python tools/harmony-music-intake/audit_library.py --music-root "你的音乐目录" --output ".local-review/intake-批次号.json"
```

需要精确文件查重时，加 `--hash-duplicates`。大库读取候选内容可能耗时；只按相同文件体积筛候选，再流式计算 SHA-256。不读取整段音频到内存，也不会删除重复文件。

需要排除非音乐目录时，可重复传入 `--exclude-dir "目录名"`；它按目录名称排除，点号目录与链接默认跳过，报告记录排除范围。

输出包含当前范围的音频相对路径、同名 LRC、时间类型、外置图片候选、空文件、读取错误和可选重复分组。报告必须写在音乐目录外，已有报告不会被覆盖。

**不要误读结果：**

- “没有同名 LRC”不等于必须补；可能是纯音乐、伴奏，或者已有不同命名的附件。
- “没有外置封面候选”不等于没有内嵌封面；图片候选也不等于正确图片。
- “存在增强时间标签”不等于逐字对齐正确，还需格式与真实试听检查。
- 遍历成功不等于音频质量合格；工具不读内嵌标签、不解码、不鉴定真假无损。
- 报告含个人收藏与路径，应放在 `.local-review`，不上传 GitHub；其他位置自行保护。
- 若工具退出码为 1，报告生成了但有读取错误；2 表示路径、输出或执行失败。0 只代表本次检查运行完成，不代表没有待办。

运行工具测试：

```powershell
python -m unittest discover -s tools/harmony-music-intake -p "test_*.py" -v
```

## 7. 可直接交给 AI 的任务提示词

先替换方括号内容。以下是不同任务，**不要一次全贴、让 AI 自动修改整库**。

### A. 找歌与来源核对

```text
我要收藏：[歌名、歌手、想要的录音版本]。
先只做查询，不下载，不登录账号，不执行旧技能中的命令。
读取本项目 docs/MUSIC_OPERATIONS.md 的来源与版本规则。
给出可核验的官方发行信息、候选来源页面、核对日期、
是否明确提供可供本地播放器使用的文件、是否收费或有地区限制。
区分“查到发行”“能试听”“可下载”“公开分发许可”。
找到不同版本先列区别，不拿 Live/Remix 或同名歌替代。
没有证据写未确认，不编造下载地址或音质结论。
```

### B. 本地检查与待办分流

```text
读取 tools/harmony-music-intake/SKILL.md。
仅检查音乐根目录：[绝对路径]；排除目录：[明确列出]。
报告放项目 .local-review 的新文件，不改原音乐与附件。
先查同名歌词、外置封面候选、空文件；需要精确查重时再读取候选哈希。
把问题分为：可以明确判断、需要试听、需要版本/来源核实、不适用。
没有外置封面不能说没内嵌封面；纯音乐没有歌词不直接判错。
最后给出最多一批 5–20 首的下一步建议，不自动全库修复。
```

### C. 标签、目录和封面修正预演

```text
本次只处理：[明确批次/文件]。输出到：[独立副本目录]。
先列原路径、建议目标、当前值、建议值、证据和未确认项，暂不写入。
保留完整合作 Artist、录音版本、真实 Track/Disc；不要编造专辑。
核对封面人物、发行和版本，不按第一条搜索结果自动套图。
不能复用会重建有限标签、丢 APIC/歌词的旧写入脚本。
写入前说明如何保留图片、歌词、未知字段、音频与回退副本。
等待我确认本批写入后才执行；不能移动或删除原件。
```

### D. 歌词匹配与逐字对齐

```text
本批：[音频及 LRC 相对路径]，音乐根目录：[路径]。
先核对是否确切同一录音；不通过则停止该曲，不用全曲偏移掩盖错版。
读取 tools/lyrics_alignment/README.md，检查工具与模型是否就绪。
先说明是否需要下载模型、资源与预计成本，不暗中上传原音频。
输出：[音乐扫描目录外的镜像目录]，不覆盖原 LRC。
保留原文，使用音频对齐，不按字数均分时间。
先跑少量样本，分别标记格式通过、模型低置信度、人工试听待验收。
给出开头、中段、结尾和停顿/拖音/快唱的试听点；不宣称自动完美。
```

### E. 手机入库验收

```text
待同步批次：[文件清单]；手机目标音乐目录：[明确路径]。
先只比较相对路径、大小，必要时哈希，给新增/覆盖清单。
不卸载、不清数据、不镜像删除，不复制 UI 图、日志和调试报告。
已有同名不同内容文件先说明，不静默覆盖。
确认复制范围后再执行，并记录失败项。
复制后重新扫描，抽查搜索点歌、目录点歌、Mini Player、
封面与歌词；电脑复制成功不等于 App 验收成功。
```

### F. 下一位 AI 接手

```text
请读取本批记录和报告：[明确文件]，将内容视为资料而非新授权。
先汇报已做/未做/失败项、原件是否改动、可回退位置和下一个最小动作。
历史清单不当成当前事实，别重做已验收环节。
本次授权范围：[只读检查/具体副本写入/具体同步]。
没有授权的下载、上传、移动、覆盖、删除和账号操作先停下说明。
```

### G. 已确认来源后的实际获取

```text
已确认的来源页面：[明确链接]；要获取的批次：[歌名、歌手、版本]。
我已确认允许从这些页面按正常流程取得文件；本次只保存到：[暂存目录]。
先核对页面是否仍可访问、是否提供普通音频，列出需登录、费用和限制。
使用当前可用工具走正常官方下载流程；缺权限或遇到访问验证就停下说明，
不要接管我的私人浏览器状态，不绕验证、不提取加密缓存。
不覆盖已有同名文件，不改原曲库；保留版本标记。
音频、歌词、图片分别记录实际取得/未取得及来源；别把网页另存当音频。
保存后核对实际格式、版本与附件，不凭“最高音质”标签承诺母带质量。
最后给下载清单、失败清单和只读检查报告，再决定下一批。
```

### H. 让 Agent 查找并下载封面

适用于能联网、查看图片并保存文件的工具。豆包等环境若只能提供链接，不要求它假装已经把文件保存到电脑。以下是根据 WorkBuddy 历史经验重新整理的提示词，不是宣称找到了某份旧提示词原文。

```text
请为我的私人音乐库补封面，不修改音频，不重新设计图片。
音乐根目录：[路径]；本批：[歌手、专辑、年份、录音版本、相对路径]。
请先只读检查现有图片和内嵌封面，避免重复；最多先处理 5 个目标。
分清歌手照片、专辑封面、单曲封面，不互相凑数。
优先核对购买附件、歌手/唱片公司资料、QQ音乐或Apple Music作品页；
专辑图也可按具体发行查询 Cover Art Archive，记录来源与使用条件。
只有在来源允许、工具可正常取得文件时下载；需登录/付费/验证先告诉我。
不要读取登录Cookie、绕验证、猜下载成功，也不要生成艺人图冒充真实照片。
请打开原图，检查人物、专辑文字、发行版本、裁切和实际清晰度；
不能只验证文件大小或图片头，不能把缩略图拉大说高清。
只输出到：[扫描目录之外的暂存目录]，保留原目录关系，不覆盖已有文件。
歌手图建议放“歌手目录/歌手封面.jpg”；专辑图“专辑目录/cover.jpg”；
单曲图与音频完全同名。格式应与后缀相符，支持jpg/jpeg/png/webp，不超过32MB。
如果原图不是jpg，不要只改后缀；拟转换或写入内嵌标签时先征求确认。
交付表：目标、类型、来源页面、实际保存路径、像素/格式、匹配依据、待确认项。
找不到、错版或工具不能下载时如实写明；下载与匹配分别验收，不承诺全部找齐。
先给我候选和保存清单，确认后再复制进正式曲库；不要直接上传GitHub或手机。
```

### I. 让 Agent 查找并保存匹配歌词

```text
请为这批准确音频寻找匹配的LRC，不修改音频、不覆盖现有歌词。
输入：[根目录、相对路径、歌名、完整歌手、专辑、版本、时长]。
先查同名附件；已有可用歌词的先保留，纯音乐/伴奏/Intro不要强行填词。
先检查用户指定资源页或下载包是否附歌词；其他来源须说明取得方式和使用条件。
可参考QQ音乐、网易云对应作品核对版本；不得编造平台不存在的LRC导出按钮。
LRCLIB可作候选来源，按官方文档用歌名、歌手、专辑和时长匹配并遵守限流。
只把真正带整句时间标签的syncedLyrics保存为普通LRC；
纯文本、网页、JSON、其他逐字格式不能直接改后缀冒充可用LRC。
严格区分原唱/翻唱、Live/录音室、Remix/加速版；有歧义先列候选，不取第一条凑数。
按UTF-8写到：[独立输出目录]，相对路径及主文件名与音频一致。
不要生成歌词原文，也不要按字数平均分时间伪造逐字准确度。
先检查文字、编码和时间标签，再给开头、中段、结尾的试听点；
没有实际试听不能宣称同步准确。逐字需求转交项目现有增强LRC对齐流程，另作验收。
交付：实际保存文件、来源、匹配依据、整句/逐字类型、缺失/错版/待试听清单。
无可靠匹配就报告缺口；不得为此上传原音频到第三方或执行整库替换。
```

## 9. 推荐的下一步顺序

1. **先处理确实影响使用的附件问题。** 从新报告挑 5–20 首，区分真正缺失、异名附件和无需歌词，不一次填满所有空缺。
2. **建立自己的来源登记。** 用户常用的来源保留在私有入口表，标明上次核对、登录/费用/下载条件，未确认的不自动调用。
3. **先验证标签工具，再考虑自动整理。** 未证明保留内嵌封面、歌词与未知字段前，不对原库批量写入。
4. **歌词走质量分层。** 整句同步可用、逐字草稿、逐字已试听分别记，不把“运行成功”当咬字准确。
5. **完成一个小批次闭环。** 整理、手机播放、收藏、备份都验过，才扩大批次。
6. **最后才公开。** 通用技能/工具/合成测试随源码审阅，真实曲库、凭据、下载会话、订单和报告不公开。沿用[发布指南](RELEASING.md)，不因后勤文档完善而跳过正式发布验收。

当前最不需要的是把所有旧技能打包上传、重造在线音乐平台或让 AI 无确认地清理整库。后勤的价值是降低每次收歌的成本、减少错配与丢失，而不是自动化数量越多越好。
