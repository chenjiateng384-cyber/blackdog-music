# 从获取音乐到入库：本地音乐收藏指南

适用于黑狗音乐（Harmony）的个人收藏工作流。整理日期：2026-11-03。

这份指南回答三个问题：音乐文件从哪里获得、怎样整理、怎样安全放进手机。它不是在线下载器，也不表示 App 新增了下载、批量改标签或自动同步功能。

文中的目录与曲目均为示例。指南没有附带歌曲、商业歌词、歌手照片或个人曲库清单。

## 1. 第一次做，只处理 5 首

不要一开始就让工具重写整个音乐库。先选自己有权使用的 5 首，覆盖普通歌曲、合作歌曲、Live、长句歌词，以及一首 WAV：

1. 保留原文件，在独立的“待整理”目录中处理副本。
2. 确认歌名、歌手、版本和音频能正常播放。
3. 配好同名 LRC，补上正确的封面。
4. 复制到手机的音乐目录，保留相对路径。
5. 在 App 重新扫描，检查搜索、封面、歌词和播放。
6. 成功后再扩大批次；新增喜欢或歌单后，导出 App 数据备份。

目标是每批可检查、可回退，不是让自动化一次改完所有文件。

## 2. 从哪里获取音乐

### 可采用的来源

| 来源 | 怎么做 | 需要确认 |
| --- | --- | --- |
| 艺术家、唱片公司的官方页面 | 使用其明确提供的下载入口，保存来源与许可说明 | 是试听，还是允许保存的完整音频；允许哪些用途 |
| 提供普通音频下载的正规数字商店 | 按官方购买、下载流程操作 | 所在地区是否可购买；是否提供可由其他播放器读取的文件 |
| 明确开放许可的音乐项目 | 从作者指定位置获取，记录具体许可版本 | 是否允许再分发、改编或商业使用，是否要求署名 |
| 自己创作或获得授权的音频 | 保留原始文件与授权记录 | 配乐、演唱和封面等相关权利是否均覆盖 |

例如，Bandcamp 官方说明购买下载提供 FLAC、WAV、MP3 等格式；在购买后的下载页面选择格式即可，不需要研究抓取接口。具体歌曲是否上架、能否购买，以当时页面和地区条件为准。[官方格式说明](https://get.bandcamp.help/en/articles/15263234-in-which-formats-can-i-download-my-purchases)

平台 App 内的“离线下载”不应直接当作可供 Harmony 使用的普通音乐文件。若是平台专用缓存或加密内容，先查看平台是否提供授权的普通文件下载方式；没有时换用明确许可的来源。本指南不提供解除保护、提取登录凭据或绕过访问验证的流程。

**自己能听，不等于可以放到 GitHub。** 例如 Bandcamp 明确说明，购买音乐并不同时取得商用或广播使用权；其他用途需要联系权利人。公开演示曲、歌词、封面也应逐项核对许可，不能因为源码采用 MIT，就把它们一起按 MIT 发布。[官方用途说明](https://get.bandcamp.help/en/articles/15263299-can-i-use-the-music-that-i-bought-in-my-youtube-video-commercial-podcast)

### 每批保留一份简短来源记录

这份记录是用户自己的资料，不必导入 App，也不要把含订单和个人信息的原件提交到仓库。

| 项目 | 记录内容 |
| --- | --- |
| 曲目与版本 | 标题、歌手、专辑、录音室版 / Live / Remix 等 |
| 来源 | 官方页面链接，取得日期；订单凭证另外私下保存 |
| 文件 | 相对路径、格式；需要精确核验时记录 SHA-256 |
| 歌词 | 来源、是否匹配当前音频、整句或逐字时间 |
| 封面 | 来源、对应歌手或专辑、许可说明 |
| 公开资格 | 允许公开分发 / 尚未确认；不把“可下载”当作授权 |
| 待检查 | 版本不确定、疑似截断、封面疑似错配等 |

## 3. 目录、文件名和版本

推荐保持人能看懂的真实目录，不必为了播放器的展示数量强行合并专辑。

```text
音乐文件/
├─ 歌手甲/
│  ├─ 歌手封面.jpg
│  ├─ 2026_专辑甲/
│  │  ├─ cover.jpg
│  │  ├─ 01_原创曲一.flac
│  │  └─ 01_原创曲一.lrc
│  └─ 单曲/
│     ├─ 原创曲二 (Live).wav
│     └─ 原创曲二 (Live).lrc
└─ 零散单曲/
```

- 音频和歌词尽量保持同目录、完全相同的主文件名，只有扩展名不同。
- Live、伴奏、翻唱、Remix、Remaster、加速版不要随意去掉版本标记。
- 同名不代表同一录音；不同版本可同时收藏。翻唱或 Remix 本身也不等于未授权作品。
- 不要用改扩展名的方式“转换格式”，也不要通过升采样或转成 FLAC 宣称音质升级。
- 使用正常中文、英文和 Unicode 文件名；避免 Windows 文件名禁用字符。遇到兼容问题先测试少量样本，不要把中文文件名全部改掉。
- 暂存目录、原件备份、歌词旧版本应放在手机扫描根目录之外，避免重复入库。

完整放置规则见[日常使用手册](Harmony-使用手册.md)。外部工具生成的 M3U/M3U8 不能据此认定已成为 Harmony 支持的导入功能。

## 4. 标签怎么整理才安全

优先核对标题、完整歌手信息、专辑、专辑艺术家、曲序、碟号和年份。字段应反映实际发行信息：

- 合作歌曲保留完整 Artist；不要为了主歌手归类，删除合作歌手文本。
- 单曲如果有真实发行专辑信息，可以保留；不知道就不要编造。不要把所有未知 Album 填成“单曲”后当正式专辑。
- 专辑目录内按真实 Track / Disc 编号，不要因为本地只收了第 1、3、6 首，就伪造为完整原专辑曲序。
- 元数据、文件命名、App 的显示筛选是三件事；修改其中一项不能替代另外两项的检查。

若使用电脑标签工具，先在副本上操作，并检查它是否保留**内嵌封面、歌词、自定义标签和音频数据**。只验证标题读回正确、时长差不多，不足以证明写入安全。

WAV 不能只检查音频头：它可以通过 RIFF 容器中的 ID3 标签保存信息；Mutagen 的 WAVE 接口明确提供 ID3 标签访问。处理这类文件应使用理解 WAV 容器的工具，不能把 MP3 的裸 ID3 写入方式直接套在 WAV 上。[Mutagen WAVE 文档](https://mutagen.readthedocs.io/en/latest/api/wave.html)

如果使用 [MusicBrainz Picard](https://picard.musicbrainz.org/quick-start/) 辅助匹配，先逐项核对发行版本和保存预览；官方也说明它不是面向大量零散单曲的一键修复器。工具提供候选，不替人决定哪个封面、发行版本一定正确。

**旧脚本提醒：** 部分历史自制标签脚本会移除旧标签，再只写回少数字段。这种方式可能丢掉原有封面或歌词，不应直接用于原件。本项目没有将这些未经验证的 WorkBuddy 脚本纳入公开工具。

## 5. 查重和“无损”怎么判断

| 检查 | 能说明什么 | 不能说明什么 |
| --- | --- | --- |
| 文件 SHA-256 相同 | 文件字节一致，可作为精确重复的强依据 | 内容相同但标签不同的文件，哈希可能不同 |
| 音频指纹或解码音频比较 | 提供相同录音的候选或音频数据对比 | 不能单靠文件名、跨格式数据哈希不同就认定不是同一录音 |
| 容器、编码信息和解码检查 | 格式能否识别、文件是否存在可检测的解码错误 | 不能证明母带来源真实，或证明不是有损转码 |
| 时长、声道、采样率、频谱和试听 | 帮助发现疑似错版、截断、异常转码 | 某个频率截止、短时长或高采样率，单独都不能证明真假无损 |

FLAC 的无损是对输入音频数据的无损压缩，不是修复原始录音。官方说明它支持多种声道与采样参数；不能把“不符合固定采样率、双声道”一律当坏文件。[FLAC 官方 FAQ](https://xiph.org/flac/faq.html)

查重应先生成“疑似重复清单”，保留两个版本供试听。不因文件小、时长短、名字相近或格式不同而自动删除；短引子、间奏也可能是完整曲目。真正处理重复文件前另行确认，并保留可恢复副本。

## 6. 封面：正确比更大更重要

先检查购买附件、艺术家或唱片公司明确提供的封面资料；需要公开演示时，优先用自己制作或有明确再分发许可的图片。搜索工具只帮助定位候选，不替代来源与授权核对。

### 歌手与专辑分开配置

- 歌手照片放在音乐根目录下的一级歌手目录，例如 `音乐文件/歌手甲/歌手封面.jpg`。
- 专辑封面放在对应专辑目录，例如 `cover.jpg`。
- 单曲独立封面可以与音频同名。
- 不要用不相关专辑图代替歌手照片，也不要把其他歌手的同名歌曲封面混进来。

具体支持的文件名、格式和大小以[使用手册](Harmony-使用手册.md)为准；修改后重新扫描。

### 补图检查顺序

1. 核对歌手、专辑、发行年份与版本，不只看歌名。
2. 打开原图检查人物、文字、裁切和实际清晰度。
3. 确认下载的是图片，而不是错误页面；文件名后缀不算验证。
4. 在列表、小窗口与完整播放页检查比例和清晰度。
5. 匹配不确定就保留默认封面并记录，别拿第一条搜索结果填满。

从平台搜索到图片、或从其图片服务器下载成功，都不表示允许再分发。私人使用资料与公开仓库演示素材分开管理。

## 7. 歌词：从根本上分清两种时间精度

获取歌词时，先查看音乐下载附件、艺术家明确提供的文本，或允许下载使用的授权歌词服务。没有合适来源时先保留无歌词状态，不抓取整个平台的歌词库。能在网页看到歌词，不等于允许批量下载或公开再分发；给已有文本增加时间轴也不会自动取得文本的授权。

普通 LRC 记录每句开始时间；增强 LRC 才能提供逐字或逐词时间。只有一句起点时，App 不能准确知道句内停顿和拖音，也不能通过按字数均分“修复”真实咬字。

推荐流程：

1. 确认音频与歌词是同一录音版本；Live、伴奏、Remaster 不直接共用时间轴。
2. 用同名、同目录的 UTF-8 LRC，在开头、中段、结尾试听整句同步。
3. 如果全曲基本固定偏早或偏晚，检查时间偏移；如果偏差越来越大或只在部分句子出现，检查版本与局部时间轴，不要用一个偏移硬修。
4. 需要逐字时，用准确音频配合原歌词做对齐，输出到独立目录，不覆盖原歌词。
5. 检查文字不变、时间递增、字词结束不早于开始；再试听停顿、拖音、快唱与两行长句。
6. 自动检查通过后仍要人工试听。低置信度片段标出来，不编造时间。

项目已有[增强 LRC 格式说明](HARMONY_ENHANCED_LRC.md)及[电脑端对齐工具说明](../tools/lyrics_alignment/README.md)，优先使用现有流程，不再新增重复工具。对齐器和模型需遵循各自许可；下载模型或进行强制对齐，也不保证所有歌曲自动达到逐字准确。

公开教学示例只使用自己创作或明确授权的短文本与音频，不把整套商业歌曲歌词上传到仓库。

## 8. 电脑到手机：先复制，后扫描

普通用户优先用系统 USB 文件传输：

1. 手机上保留一个明确的音乐根目录。
2. 复制这批新增音频、LRC 和图片，保持相对路径；不用“镜像删除”清理目标目录。
3. 复制完成后抽查文件能否打开；重要批次可比对相对路径、大小和哈希，单看数量不够。
4. 在 App 选择音乐根目录并重新扫描。重装后可能需要重新授予目录读取权限。
5. 从歌曲、歌手、专辑、文件夹和搜索分别点播样本，检查歌词与封面。

开发者使用 ADB 也应先用小样本验证中文、空格和符号路径，明确目标范围。旧设备上的某次传输故障不能推导出“中文路径一律不可用”。本指南不提供批量删除手机存储的命令。

验收截图、调试日志、临时报告留在电脑，不作为音乐附件复制到手机；本轮文档整理没有向手机写入任何文件。

## 9. 两份备份，各管一件事

| 备份 | 保护什么 | 放在哪里 |
| --- | --- | --- |
| 音乐收藏备份 | 原始音频、LRC、图片和来源记录 | 独立磁盘或用户控制的其他位置，不只保存在手机 |
| `.harmonybackup` | App 管理的喜欢、歌单、历史、设置等，范围见使用手册 | App 外部，再复制一份到电脑；不提交 GitHub |

App 备份不包含原始音乐，不能替代音乐文件备份。复制音乐也不能替代收藏、歌单和历史备份。恢复能力应在隔离环境验证，不能拿唯一的数据副本做卸载实验。

## 10. 每批入库验收清单

- [ ] 来源明确；需要公开的素材另有再分发许可说明。
- [ ] 音频完整可播，版本与命名相符。
- [ ] 标签与曲序可靠，合作信息没有丢失。
- [ ] 写标签前有副本；写后封面、歌词和额外标签仍在。
- [ ] 疑似重复只是标记，没有未经确认删除。
- [ ] 封面语义正确，不是“下载成功就算正确”。
- [ ] 歌词与当前录音匹配，普通 / 增强精度说明准确。
- [ ] 手机目录、中文文件名与附件完整，重新扫描后可用。
- [ ] 喜欢和歌单正常；重要数据已导出备份。

## 11. 哪些经验适合公开

本指南吸收了本地 WorkBuddy 音乐整理、版本查重、标签与封面检查、歌词验收及手机同步资料中的通用经验，并重新编写。原有技能全文、脚本、市场技能图标和个人曲库没有随之复制；参考材料的存在不等于获得代码或素材的再许可。

适合公开：安全工作流、合成目录示例、匹配规则、验收清单，以及项目已有且授权清楚的工具说明。

不随源码公开：私人音乐、商业歌词、未经核实许可的图片、订单、账号凭据、个人路径、曲库数据库、浏览器状态和历史操作记录。旧下载器、直接覆盖标签的脚本和批量清理脚本未通过独立安全与许可审查前，不作为公开可执行工具交付。

这份文档可作为发布候选资料；它不代表整个仓库、历史提交或全部第三方素材已通过发布审核。
