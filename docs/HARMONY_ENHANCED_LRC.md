# Harmony 增强 LRC 规范

## 目标

普通 LRC 只有每行开始时间，无法表达一句歌词中的停顿、咬字和延音。
Harmony 使用增强 LRC 的“字开始时间 + 字结束时间”实现准确推进。

## 文件要求

- UTF-8 编码。
- 与音频完全同名，例如 `七里香.flac` 对应 `七里香.lrc`。
- 放在音频同一目录，重新扫描后自动关联。
- 时间精度建议至少 10 毫秒。
- 不修改音频文件本身。

## 时间格式

```text
[00:02.000]<00:02.000>你<00:02.300><00:02.650>好<00:03.200>
```

含义：

- `[00:02.000]`：整行开始。
- `<00:02.000>你<00:02.300>`：`你` 从 2.000 秒唱到 2.300 秒。
- 2.300–2.650 秒没有文字，是一次真实停顿，绿色推进必须停住。
- `<00:02.650>好<00:03.200>`：`好` 从 2.650 秒唱到 3.200 秒；如果是长音，就把结束时间放在长音真正结束的位置。

没有停顿时可以连续书写：

```text
[00:05.000]<00:05.000>窗<00:05.260>外<00:05.540>的<00:05.790>雨<00:06.300>
```

Harmony 同时兼容只有字开始时间的普通增强 LRC，但只有明确提供字结束时间，才能正确表达停顿和延音。

## 生成要求

生成工具或 Agent 必须实际读取音频并进行 forced alignment（强制对齐），不能只根据整行时长平均分配。

每个字或英文单词都必须满足：

1. 开始时间对应真实发声起点。
2. 结束时间对应该字发声或延音结束。
3. 停顿必须保留为空白时间段。
4. 时间必须单调递增，结束时间不能早于开始时间。
5. 不得改变原歌词文字、标点和行顺序。
6. 伴奏、前奏和间奏不虚构歌词。

## 给歌词 Agent 的任务模板

```text
请读取我提供的音频文件和同名普通 LRC，执行逐字/逐词音频强制对齐。

输出 UTF-8 增强 LRC，严格使用下面的 Harmony 格式：
[行开始]<字开始>字<字结束><下一字开始>下一字<下一字结束>

示例：
[00:02.000]<00:02.000>你<00:02.300><00:02.650>好<00:03.200>

要求：
1. 必须根据真实人声对齐，禁止平均分配整行时间。
2. 停顿保留为前一字结束到后一字开始之间的空档。
3. 拉长音的结束时间必须落在真实尾音结束处。
4. 中文按字，英文优先按实际演唱单词或音节。
5. 时间精度至少 10 毫秒并严格递增。
6. 保留原歌词、Metadata 和行顺序。
7. 输出文件与音频同名，只把扩展名改为 .lrc。
8. 无法可靠对齐的行必须单独列入报告，不能猜测后伪装成准确结果。
```

## 验收

- 在 Harmony 中播放并观察绿色边界是否贴合每个发声字。
- 遇到停顿时边界应停住。
- 遇到延音时边界应在对应字内持续推进。
- 整体提前或延后时，调整歌词偏移量；不要整体重写所有时间戳。
