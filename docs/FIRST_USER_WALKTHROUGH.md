## 2. 实际发现并修复的问题

### P1：Windows 启动脚本丢失参数

脚本声明了额外参数，但 doctor、run、构建等入口没有完整传递。用户指定设备或构建参数时，操作可能与预期不同。

修复：统一透传这些入口的参数；debug APK 也使用已有中文项目路径处理，保留原命令失败码。

验证：先补回归测试，在原实现上实际失败于 `--help` 未传递；修复后通过。回归覆盖参数、设备 ID、失败码和映射释放，不只是检查代码文字。

### P1：解压源码使用外部中文 SDK 路径时构建失败

原环境 SDK 位于原项目内部，已有项目路径映射掩盖了外部 SDK 的情况。新目录使用外部中文 SDK 后，Gradle / Flutter 加载路径出现乱码，找不到插件脚本。

先试过只在项目配置中显式读取 UTF-8，但上游加载器还有相同问题；这一局部尝试已撤回，没有修改已安装 Flutter SDK。最终沿用现有临时盘符机制，同时处理外部中文 SDK 路径，在 `finally` 恢复环境并释放本次映射。

验证：同一隔离源码先失败，修复后实际生成 APK；Windows 模拟 SDK 回归也覆盖外部非 ASCII 路径和映射释放。原因与 Java Properties 字节流默认编码有关，不是歌曲或播放器卡顿。[Java 官方说明](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/util/Properties.html)

### P1：脚本强制覆盖使用者的下载源

原脚本无条件写入两个镜像环境变量，既覆盖使用者配置，也让新用户不清楚依赖从哪里取得。

修复：不再强行赋值，沿用 SDK 默认值或使用者显式设置。回归分别验证自定义值保留与未设置时不注入镜像。网络受限时由用户参考[官方镜像指南](https://docs.flutter.dev/community/china)决定，而不是自动替用户信任一个来源。

### P1：空库首页缺少下一步，智能播放文案与定义冲突

首次打开没有音乐时，用户只看到不能点的播放入口；“常听优先”的智能播放空文案还容易让人以为必须先积累历史。

修复：只改现有位置的文案，不加新卡片、不动布局或算法。空库提示去“我的”选择主音乐目录；有曲库但无候选时说明可以手动点播。测试确认空库按钮仍禁用、原导航和搜索可使用。

### P2：普通用户被开发与后勤材料淹没

新增[第一次使用](QUICK_START.md)，按“准备几首歌 → 复制 → 选目录 → 扫描 → 播放/备份”说明。开发、发布和 AI 后勤资料放在需要时再读的位置。

补充了 APK 与源码区别、系统目录按钮灰色、0 首、缺封面、缺歌词、后台、升级失败等处理。开发运行步骤要求先确认 Android 设备，避免误选当前没有工程支持的 Windows/Chrome。

## 3. 纠正一项先前判断：基号不是分架构 APK 编号

较早报告把“源码基号 11、ARM64 实包 2011”直接推断为默认构建号回退风险，这不准确。

本轮检查实际 APK，并读取当前固定 Flutter 插件实现，确认 ARM64 拆分包使用 `基号 + 2000`。将基号设为 2012 的试验实包变成 4012，已经移出交付目录隔离，未安装、未上传、未分发。
